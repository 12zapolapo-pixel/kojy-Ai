# Database Architecture

KojyAI uses **one PostgreSQL 16 database** (with the `pgvector` extension)
for everything, plus a small local SQLite file for the global emote cache.

| Store | What lives there | Why |
|---|---|---|
| Postgres | Users, orgs, sessions, bots, scripts, Composer projects, analytics, audit/security logs, billing, Delegation sessions **and** Delegation semantic memory (`delegation_memories.embedding vector(384)`, HNSW index) | One relational store; pgvector gives similarity search without a second database |
| Redis | BullMQ job queues, WebSocket fan-out (pub/sub), rate limits, bot-control messages | Fast, ephemeral coordination |
| SQLite (`$SQLITE_DIR/emote-cache.db`) | Global Highrise emote catalog | Shared reference data with no tenant dimension |

## Where the schema lives

- `packages/db/src/schema.ts` — the only schema definition, imported by both
  the API and the worker (`apps/*/src/db/schemas/schema.ts` just re-export it).
- `packages/db/migrations/` — SQL generated by `pnpm db:generate`.
- The API applies pending migrations on boot (`DB_AUTO_MIGRATE=false` to
  disable); the worker never migrates.

## Conventions

- Serial integer primary keys internally; every public-facing row also has a
  `uuid`, and the API returns that as `id`.
- All timestamps are `timestamptz`. `updatedAt` is maintained by Drizzle's
  `$onUpdate` (Postgres has no `ON UPDATE CURRENT_TIMESTAMP`).
- `jsonb` only where the shape is genuinely flexible; typed with `$type<>()`
  where it's known.
- Upserts use `onConflictDoUpdate` against a real unique key
  (`analytics_snapshots` has a `NULLS NOT DISTINCT` key so org-level rows,
  where `bot_id` is NULL, still upsert).

## Backups

The worker runs `pg_dump --format=custom` daily into `BACKUP_DIR` and keeps
`BACKUP_KEEP_DAYS` (default 14); see `docs/DEPLOY_ORACLE.md` for restore.
